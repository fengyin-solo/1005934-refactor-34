# 光伏电站运行维护管理平台

面向电站台账、组串阵列、逆变器、汇流箱、跟踪支架、组件清洗、告警处置与发电结算的一体化光伏电站运行维护工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 合同到期与续签的统一判定

历史上同一份合同在合同页、到期提醒、考核页各有一套算法，结论互相打架。现在三处
（`views/contract`、`views/renewal`、`views/assessment`）**只从同一个取数入口取结论**，
页面自身不做任何到期判断：

- 判定准绳：**合同期限的最后一天（`合同期限止`）这一栏**。到期前 30 天进入续签窗口，
  窗口内为「待续签」，过了期限止仍未续签为「已过期」。
- 续签状态只描述续签流程，统一五档写法（`未到续签窗口 / 待续签 / 审核中 / 已续签 / 无需续签`），
  定义只存在于 `src/domain/contract-lifecycle.ts` 这一处；手工填写只用于「提交续签申请」这一个动作。
- 考核指标是否达标只产生「考核结果」（合格/不合格/未考核），不再参与到期判定。
- 规则纯函数化：`assessContract(row, reviews)` 是唯一判定入口，`isRenewalDue` / `canSubmitRenewal`
  等派生判断也共用这一份。
- 历史已终止合同**冻结留档**（`frozen`），期限推移不再重算，手工填的历史续签状态原样保留。
- 存量合同在应用启动时由 `src/data/migration.ts` 做一次性、幂等的回填：兼容老的单日期
  「合同期限」（视为只登记了到期日，起期留空不臆造）与「起 至 止」区间文本，按合同期限止
  重算结论并把脏的续签状态收敛到统一写法。
- 续签申请与对接人员提交的履约考核结果都落 **待审清单**（`pv-plant-ops:reviews`）：
  续签审核通过则期限止顺延一年、续签次数 +1；考核审核通过才回写合同。**同一合同已有待审核
  续签申请/履约结果时，重复提交不重复入列，只算一次。**
- 运维人员页按「在岗 + 持证有效」与合同的对接人员对账：在岗但证书过期、对接人员已离岗、
  合同进入待续签/已过期或考核不合格等问题会同时挂到人员与合同上。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 合同相关页面（合同页、到期提醒、合同考核、待审清单）不走通用状态机，统一走
  `frontend/src/api/contract-service.ts`，判定规则在 `frontend/src/domain/contract-lifecycle.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`（合同/人员及 `SEED_REVIEWS` 待审清单）。
- 状态流转只允许在 service 层里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `pv-plant-ops:entries`（业务数据）、`pv-plant-ops:reviews`
  （待审清单）、`pv-plant-ops:schema-version`（回填版本号，清掉后会按存量合同重新回填一遍），
  或调用 `resetModule(模块)`。
