# 光伏电站运行维护管理平台

面向电站台账、组串阵列、逆变器、汇流箱、跟踪支架、组件清洗、告警处置与发电结算的一体化光伏电站运行维护工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 合同到期与续签的统一判定

合同页、到期续签提醒、合同履约考核过去各算各的（看状态快照 / 看手工续签状态 /
看考核指标是否达标），同一份合同会得出三种结论。现在统一收口，规则只有一份：

- 唯一判定依据：**合同期限的最后一天**。到期前 30 天进入续签提醒窗口；
  逻辑在 `frontend/src/domain/contract-lifecycle.ts`，三个页面只读它的结论，
  读写统一走 `frontend/src/api/contract-service.ts`。
- **续签状态统一写法**且只由流程写入：未启动 / 待续签（窗口推导态，不入库）/
  审核中 / 已续签 / 不续签，页面不再手工填写；考核是否达标只生成履约结果，不参与到期判定。
- 续签申请与履约结果都落 **待审清单**（`review`）：续签通过自动顺延合同期限一年，
  履约结果通过后才写回合同。同一份合同同类事项在途时重复提交一律拦截，只算一次。
- 历史已终止合同按当时结论写「留档结论」封存，不再重新判定；存量合同首次打开 v2 时
  一次性迁移：已终止留档，其余按合同期限回填（过期→待续签，未到期→履行中）。
  旧数据键 `pv-plant-ops:entries` 自动迁移到 `pv-plant-ops:entries:v2`。
- 运维人员的持证（证书有效期）与在岗情况按「所在电站 ↔ 服务范围」对齐合同结论：
  履行中 / 待续签合同若无「在岗 + 证书有效」人员，合同页标「持证在岗缺口」。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
  运维合同例外：合同 / 续签 / 待审的流转集中在 `api/contract-service.ts`，
  判定规则在 `domain/contract-lifecycle.ts`，任何页面不得自写到期算法。
- 想回到初始数据：清掉浏览器里 `pv-plant-ops:entries:v2` 这一项，或调用 `resetModule(模块)`。
